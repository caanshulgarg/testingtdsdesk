Checked, no finding:
- **SQL rules:** the file is one transaction (`begin` … `commit`) with `lock_timeout` 10 s. It has no drop, truncate or delete. The columns use `add column if not exists`, so the file is safe to run twice; the test runs it twice and no row changes. Both functions are security definer with `search_path = public, pg_temp`. Each has `revoke all … from public, anon, authenticated, service_role` and no grant. Values are cast only after the regex or `in ('true','false')` checks. The jsonb inputs are type-checked.
- **Old bodies:** a body without `gst` (2.4.1) never blanks or overwrites the stored values. A lower AlterID never overwrites. But see H1: the values are not tied to a version.
- **Injection and XSS:** the values are written through jsonb and parameterised RPC. The app uses them only in `supplyClass`, `isRcm` and `blocked` logic; grep found no `innerHTML` or template rendering of `nature`, `regType`, `country` or `taxability`.
- **What is kept:** exactly the 18 approved paths are added to the strip, and `run_parse_gsttype` and gsttype242_test check that nothing else is kept. No AI anywhere.
- **Older-bridge interop:** `dayVouchers` adds `gst` only when parse found one of the tags. `tally_recorder_keep_vouchers` keeps the key (`x || …`).
