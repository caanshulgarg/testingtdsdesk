Checked, no new finding:
- **SQL:** this is still add-only, one transaction, safe twice (the test runs it twice, no row changes), security definer with `search_path = public, pg_temp`, `revoke all … from public, anon, authenticated, service_role`, and no grant. The `=` guard and `distinct on … order by alter desc` never write onto a version the entry path did not store; a held entry is skipped.
- **Financial cases on the 24 real 7.1 entries** (run_migration72 §2/§3, run_parse_gsttype): SEZ (S03), export with payment (S05), export under LUT (S06, Exempt), nil (S10), reverse charge (P03), blocked 17(5) (P04L true, P04 false) and exempt purchase (P05) are unchanged, and `mixed` is false on all of them.
- **XSS:** `gst_mixed` and `gst_alter_id` are a boolean and a number. `gstMixed` is never rendered, and the values reach the app only through the JSON REST read.
- **DoS:** `val`/`any` use `openRe` plus `[^<]*`, so they are linear. `kind(lead)` is recomputed per unit, which is linear in the number of GST lines. The 500-item real invoice takes 34 ms.
- **The Tally request:** no bridge-go change in the range. `liveFetchField` and `liveKeepGST242` are as reviewed in round 1.
- **Interop:** a body without `gst` (2.4.1, ByNumber) leaves the values and `gst_alter_id` as they are. The app then treats them as stale and marks them carried. A cloud without 72 still falls back to HEADS and then HEADS_OLD on "does not exist".
- **Pre-existing, not counted:** `openRe` (`parse.js:23`, from 2.3.1) is quadratic when a list opener is followed by a long run of whitespace with no `>`. `<ALLLEDGERENTRIES.LIST` followed by 40,000 spaces takes 1.3 s in parseDay both before 2.4.2 (176dcfb68) and now. 200,000 spaces take about 50 s in `gstType`. `cutOut`'s own tag pattern has the same shape. This needs a crafted body from a holder of the bridge token or an uploader of the book. Suggest a follow-up: `(?:\s[^<>]*?)?` with the self-closing check done outside the regex, or one `[^<>]*>` and then a test that the match does not end in `/>`.

Verdict: 0 High, 2 Medium, 2 Low open
