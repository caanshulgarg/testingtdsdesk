# Post to Tally: the reasons table

What FinCom says when an entry did not go into Tally. The program reads this same table (src/js/62-post-reasons.js,
`POST_REASONS`); this page is for the owner to review the words. The first row whose message matches is used.

"X" stands for the name in the message (a ledger, a voucher type). A message that matches no row is shown as
"Tally said: <message>", is not offered for Post again until someone has read it, and is written to the browser's
console and to the firm's activity log (once a message).

| Message seen | Plain reason | How to fix | Can post again | Status | Key |
|---|---|---|---|---|---|
| its FinCom id is taken · already sent from this computer on … · Already in Tally (voucher no. …) · Held as posted … | This bill is already posted (FinCom holds it as posted) | Nothing to post again. If it is really not in Tally, an owner undoes the posted mark first (More → This entry is not in Tally). | No | Not posted: stopped before sending | `duplicate` |
| Ledger 'X' does not exist · Failed: ledger 'X' is not in Tally — create it · Ledger “X” is not in Tally | The ledger “X” is not in Tally | Create the ledger “X” in Tally, or choose Tally's own ledger in the bill, then post again. | Yes, after the fix | Not posted: Tally refused it | `ledger` |
| Voucher type 'X' does not exist · Failed: voucher type 'X' is not in Tally — create it | The voucher type “X” is not in Tally | Create the voucher type “X” in Tally, or choose another one in Client setup → Tally, then post again. | Yes, after the fix | Not posted: Tally refused it | `vchtype` |
| Voucher date is outside the period of the company · Failed: the entry's date is not within the company's books in Tally | The bill's date is outside the financial year or the period allowed in Tally | In Tally, open the year that holds the bill's date (or allow that period), or correct the bill's date, then post again. | Yes, after the fix | Not posted: Tally refused it | `period` |
| This computer posts only to X (PostOnly); posting to Y refused · not on the bridge's allow-list · Posting to Tally is switched off (AllowImport) · Another bridge is the main bridge | This computer may not post to that company | An owner allows posting to this company on that computer (FinCom → Tally page → the computer's posting settings), then post again. | Yes, after the fix | Not posted: stopped before sending | `postonly` |
| X may post only to Y, but its books in FinCom's cloud come from Z · Choose the Tally company … · Tally created it in X instead | The Tally company is not the one this client posts to | Choose or confirm the Tally company in Client setup → Tally (and open that company in Tally), then post again. | Yes, after the fix | Not posted: stopped before sending | `wrongco` |
| Waiting for Tally: X is open in more than one Tally | The company is open in more than one Tally | Close it in all but one Tally, then post again. | Yes, after the fix | Not posted: stopped before sending | `many` |
| Waiting for Tally: X is not open — open it in TallyPrime · Tally did not show X for two minutes. Open it in TallyPrime and post again. | The company is not open in Tally | Open the company in TallyPrime on the Tally computer, then post again. | Yes, after the fix | Not posted: stopped before sending | `notopen` |
| Waiting for Tally: TallyPrime is not open · Tally is not answering on its port · FinCom Bridge on X is not running | Tally is not running on the Tally computer | Start TallyPrime (and FinCom Bridge) on the Tally computer, then post again. | Yes, after the fix | Not posted: stopped before sending | `tallydown` |
| Waiting for Tally: another posting to this Tally is going on · Some of these entries are already waiting to be posted · Tally is busy (a report, a pop-up …) | Another posting is going on | Wait for that posting to finish (close any open report or pop-up in Tally); this one can be posted after it. | Yes, after the fix | Not posted: stopped before sending | `busy` |
| Could not check Tally, not posted. Try again. · Waiting for Tally: … | Tally could not be checked first, so nothing was sent | Make sure Tally is open on the Tally computer, then post again. | Yes, after the fix | Not posted: stopped before sending | `checkfailed` |
| Nothing to post · Choose a bill that is ready to post · The entry has no valid date · Retry not possible: this bill was deleted in FinCom | The bill is not approved, or its details are incomplete | Open the bill, complete it and approve it (restore it first if it was deleted), then post. | No | Not posted: stopped before sending | `notapproved` |
| Sent to Tally, but no answer came · not known whether Tally got it · Checking whether it reached Tally · Tally did not answer | No answer from Tally: it may or may not be in Tally | Look in Tally's Day Book for the bill's date before anything else. If it is there: mark posted with its Tally id. If not: release it and post again. | No | Needs review | `noanswer` |
| Tally replied 'created', but the entry cannot be found … · Tally's reply: … · Tally did not confirm it · not yet read back | Tally's reply was incomplete: it said it took the entry, but FinCom could not find it in Tally | Look in Tally's Day Book for the bill's date. If it is there: mark posted with its Tally id. If not: release it and post again. | No | Needs review | `incomplete` |
| Tally reported an exception. Check the ledger names and the voucher type. · Voucher Number 'X' already exists! | Tally refused the entry as it was sent (an exception in Tally) | Check the ledger names, the voucher type and the voucher number in Tally, then post again. | Yes, after the fix | Not posted: Tally refused it | `exception` |
| Tally ignored it (it may already exist). | Tally ignored it: an entry with the same details already exists | Look for the entry in Tally; if it is there, an owner marks this one posted with its Tally id. | No | Not posted: Tally refused it | `ignored` |
| The posting stopped part-way (the computer or the bridge was restarted). | The posting stopped part-way (the Tally computer or the bridge was restarted) | Post again; what is already in Tally is not sent twice. | Yes, after the fix | Not posted: stopped before sending | `restarted` |
| Cancelled before the Tally computer took it · Cancelled in FinCom; nothing more is sent to Tally | The posting was cancelled before it reached Tally | Post again when you want it in Tally. | Yes, after the fix | Not posted: stopped before sending | `cancelled` |
| Tally did not create it. · Failed: Tally refused it (…) — correct it | Tally did not create the entry | Open the bill, check its ledgers and date, then post again. | Yes, after the fix | Not posted: Tally refused it | `notcreated` |
| The posting stopped before anything was sent. | The posting stopped before anything was sent | Put right what the message says, then post again. | Yes, after the fix | Not posted: stopped before sending | `notsent` |

Status: the line the entry shows on the Errors tab. "Needs review" means Tally may have the entry: look in Tally first;
the owner then marks it posted (with Tally's id) or releases it and posts again.
